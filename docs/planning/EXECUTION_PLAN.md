## 1. Finish November 2025 (by Nov 30)

Goal: Have **offer, messaging, content, and basic operations** ready so you can start selling and fulfilling boxes.

### 1.1 Offer & Rules
- Freeze subscription model:
  - Step Starter – 1 month – ₹999
  - Path Explorer – 3 months – ₹2,699
  - Life Learner – 6 months – ₹4,999
- Confirm non‑negotiables (no classes, only IG, physical kits only, one plan with duration options).
- Set internal targets:
  - Material cost per box: aim for ₹300–₹600.
  - “Personalize activities, not the price” as a strict rule.

**Output:** short internal note (could be a Notion page or doc) summarizing the above.

### 1.2 Instagram Foundations
- Write at least **5 reel scripts** for:
  - Story-based child learning reel.
  - Founder narrative (“Why I built this unschool movement”).
  - Box unboxing.
  - Activity showcase.
  - “How our box works” explainer.
- Draft matching **captions** that:
  - Use the brand story from the blueprint.
  - End with:  
    “DM **UNSCHOOL** to join the movement — monthly personalized curiosity kits.”

**Output:** one document with 5 scripts + 5 captions ready to paste into Instagram.

### 1.3 Landing Page Content
- Define the first version of the landing page:
  - Hero section (headline, subheadline, primary CTA).
  - “How it works” in 3–4 clear steps.
  - Plans section (1 / 3 / 6 months) with a simple comparison.
  - 3–5 testimonials (real or placeholder to be replaced later).
  - FAQ with 6–8 parent questions and answers.

**Output:** a single page of copy (or a wireframe) that can be implemented later.

### 1.4 Internal Operations Basics
- Design:
  - Child interest form (age, interests, goals, constraints).
  - Simple spreadsheet to track:
    - Cost per box vs target.
    - Reusable items.
  - Basic inventory list of reusable items.
  - Box packing checklist (from order → pack → pickup/drop).

**Output:** interest form + spreadsheet + inventory list + checklist, all in a place you actually use.

### 1.5 Pricing Visual
- Create a **3-option pricing comparison** that highlights:
  - Plan names, durations, total price.
  - “Best value” tag for Life Learner.
  - Consistent messaging from the blueprint.

**Output:** one visual (Figma/Canva/image) that can be reused on:
  - Landing page.
  - Instagram posts or stories.

## 2. December 2025 – Stability & Observability

Goal: Make the system **reliable** and **understandable** when real parents start using it.

- Fix any critical bugs in:
  - Plan generation and logic (backend/agents, backend/utils).
  - Activity tracking and logging.
- Improve monitoring and diagnostics:
  - Make sure you can easily see what’s happening when a plan is generated or a box is prepared.
  - Align with any notes you keep in monitoring/diagnostic docs.
- Developer experience:
  - Ensure you can set up the project from scratch using `README.md` and `docs/DETAILED_README.md`.
  - Note any painful steps and smooth them over time.

---

## 3. January 2026 – UX & Learning Model

Goal: Make the **parent and child experience feel smooth** and ensure plans feel genuinely personalized.

- Parent & child journey:
  - Smooth main flows (from interest form → subscription choice → first box).
  - Make sure copy matches how real parents actually talk and think.
- Plan quality:
  - Use real data (what parents pick, how kids use boxes) to refine:
    - Hybrid Monthly plan rules.
    - Holistic Fusion plan rules.
  - Update your internal plan format docs whenever rules change.
- Performance:
  - Identify any slow or confusing parts of the journey and simplify or optimize.

---

## 4. February 2026 – Automation, Scale & Cleanup

Goal: Reduce manual work, handle more parents smoothly, and keep the system clean.

- Automation:
  - Improve any sync or admin flows you rely on (e.g., spreadsheets, forms, inventory tracking).
  - Standardize repeatable processes (monthly planning, packing runs, IG content).
- Scale & resilience:
  - Make sure you have reasonable limits, timeouts, and fallbacks for any external tools you use.
  - Keep staging / “test” flows separate from real parent flows.
- Cleanup:
  - Remove or archive old experiments and backups you no longer need (once safely saved elsewhere).
  - Simplify any duplicated logic in your tools and docs.
